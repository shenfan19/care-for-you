# Care for You：轻量 LM 后端

一个独立的小进程，把游戏里每个角色的需求、心情、虚弱度当作 Life Matters 风格的模型状态变量来积分。它与 backend_example_ai 并列，用同一份接口，游戏里改一下 backend_url 就能换。接口见仓库根目录的 README_backend_protocol_ai.md。

它只做积分。随机事件、台词、谁向谁求助都不管，握手时声明了，游戏把这几样交给内置后端。

## 运行

```
pip install pyyaml
python server.py 8788
```

游戏设置的高级设置折叠区里，backend_provider 选 http，backend_url 填 http://127.0.0.1:8788/。不用动 needs_source，后端每次回应都会声明它驱动了哪些变量。

调试用的地址：

- GET /：握手信息，含模型列表
- GET /stats：请求数、处理耗时的均值和最大值
- GET /state：每个角色当前的全部内部状态变量

测试与自检：

```
python test_lm_backend.py
python lm_engine.py
```

test_lm_backend.py 覆盖表达式白名单、模型与类载入、类的派生、对表、增量指令、模型之间的耦合、步长收敛、稳定性、HTTP 协议。lm_engine.py 直接运行是自检：每一类角色空放若干天，状态不越界，没有 NaN。

## 它怎么工作

- 模型：models 文件夹里一个模型一个 YAML 文件，沿用 LM 的写法：metadata，parameters，variables，equations，每条方程的 dynamics 是 Python 语法的表达式，step 是这一小步的小时数，写成 x 加上目标减 x 乘以一减 exp(负 step 除 tau) 这样的一阶松弛。表达式只允许数字、四则乘方、比较、and or not、三元式和 min max abs exp log sqrt pow floor tanh sin cos，别的一律拒绝。
- 辅助量：auxiliary 里的量每小步先算，可以被方程引用。
- 模型共用一个命名空间：一个模型可以直接读另一个模型的状态，比如睡眠模型读脱水缺口，社交模型读睡眠债。名字重复在载入时报错。
- 方程顺序：按 priority 从大到小依次更新，后面的方程读到的是前面刚更新的值，和 LM 引擎一致。
- 步长：一次请求推进的游戏分钟数拆成不超过 15 分钟的小步，至多 240 步。游戏的请求间隔不同，结果几乎不变，测试里有步长收敛的检查。
- 游戏变量与状态变量的映射：模型里的 drives 把一个状态变量线性映射到游戏里零到一的变量，lo 大于 hi 就是反向，比如饥饿是一减饱腹。
- 对表：玩家的动作直接改游戏里的需求，后端不知道做了什么动作。每次收到快照，对每个 drive 比较快照值和上次回过去的值，差超过 0.03 就认为被动过，按映射反推状态变量，然后继续积分。第一次见到的角色同样按快照反推，所以后端重启、游戏换存档都不用同步状态。
- 增量：回给游戏的是 need、mood、frailty 增量，不是绝对值，请求飞行期间玩家的动作不会被盖掉。
- 角色编号稳定，快照里没有的角色会被忘掉。

## 六个模型

每个角色可用的变量取决于它是人、动物还是花草。

- hydration：失水缺口。驱动口渴，花草的土干了是同一个缺口。睡着、住院时失水慢，发热时快。来源 LM 的 renal_fluid 组件，缩小成单室。
- energy：饱腹和血糖。驱动饥饿；血糖向饱腹决定的目标松弛，糖尿病放大升糖幅度，血糖过高或过低折算成血糖压力进入心情。睡眠债会加快饥饿。来源 glucose_insulin 与 appetite_intake_regulation。
- sleep：睡眠压力和睡眠债。驱动疲倦；清醒时上升，夜里加成，脱水和饥饿使它更高，睡着时回落；压力超过 0.85 且清醒时攒睡眠债，睡着时还债。来源 nervous_sleep_stress 的睡眠部分。
- social：孤独、无聊、压力、心情。驱动想有人陪、想玩和心情；压力向需求最高者超过 0.5 的部分松弛；心情向目标松弛，目标由最高需求、睡眠债、血糖压力和性格偏移决定。来源 nervous_sleep_stress 的压力与情绪部分。
- body：活动缺口、稳态负荷、虚弱度。驱动想活动和虚弱度；稳态负荷长期累积需求超限、睡眠债和压力；虚弱度向体质基线加负荷的贡献松弛，上升慢，回落更慢，住院时回落快。体质基线是第一次见到这个角色时的虚弱度。来源 aging_health_summary 与 musculoskeletal。
- upkeep：洗澡、尿布、作业、砂盆、花草的光照肥料修剪。纯累积，没有对应的 LM 组件，只为了让一个角色的全部需求由同一套积分驱动。尿布与失水缺口有一个小耦合。

模型之间的主要耦合：

- 脱水推高睡眠压力，所以不喝水的人更困。
- 睡眠债加快饥饿，让睡不好的人更容易饿。
- 睡眠债、血糖异常、最高需求共同压低心情。
- 最高需求、睡眠债、压力累积成稳态负荷，再慢慢拉高虚弱度。这是“长期被忽视的后果”的唯一来源。

## 一个 human 类，派生到每个角色

classes.yaml 定义派生链，只写和模型默认值不同的参数：

- 链：organism，大类 human 或 animal 或 plant，human_阶段 或物种名，再叠疾病。越靠后越具体，后面覆盖前面。
- 人：一个 human 类，婴儿、幼儿、儿童、少年、成人、老人按年龄阶段改速率，少年成人老人用模型默认值。
- 动物：animal 是默认，猫、狗、兔、仓鼠有自己的速率，其余沿用 animal 默认。
- 花草：六种花草各自的失水、光照、肥料、修剪速率。
- 疾病：糖尿病放大升糖，关节炎、帕金森、骨折加快活动缺口，心脏病、帕金森、高血压放大虚弱倍数，抑郁压低心情。
- 性格不在这里：游戏把性格折算好的速率倍数 rate_mult、心情偏移 mood_offset、虚弱倍数 frailty_mult 随快照发来，单一来源。

速率的数值对表游戏内置的速率表，所以平均需求曲线量级一致，不同在于模型之间的耦合。

## 加一个模型或一个类

- 加模型：在 models 里放一个 YAML，名字不要和已有的重复，用 priority 决定更新顺序，用 drives 把状态变量接到游戏变量上。
- 加类：在 classes.yaml 的 kinds 里给新物种指定大类，classes 里写它与默认值不同的参数。
- 改完运行 python lm_engine.py 和 python test_lm_backend.py。

## 限制

- 事件、台词、策略不是它的事，也就是说单独用它，游戏里的夜尿跌倒这类事件仍然是内置规则触发的。
- 玩家的动作只能通过需求被动对表，模型不知道是喝水还是吃饭，所以没有动作特有的生理效应。
- 没有 LM 的校验、优化、蒙特卡洛，只有前向积分。所有系数都是经验取值，尚未校准，只保证量级和方向合理。欢迎对模型提意见和批评。
- 进程内保存状态，重启后靠快照重新对表，丢掉的只有睡眠债、稳态负荷这类慢变量。
- 单进程单线程积分，一个玩家用绰绰有余，不是为很多玩家同时在线设计的。
